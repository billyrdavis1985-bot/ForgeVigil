# forgevigil.com

The ForgeVigil website: static pages generated by `website/build.py` with the Python standard
library. It explains ForgeVigil and does not run it, so it has no server code, forms, cookies or
analytics, and nothing here calls a model, touches `var/` or adds a dependency.

```bash
python3 website/build.py          # writes website/dist/ (git-ignored)
python3 -m unittest tests.test_site -v
```

Preview locally with `python3 -m http.server -d website/dist 8000`, then open
`http://localhost:8000/index.html`. Extensionless links such as `/walkthrough` resolve on
Cloudflare Pages but not in `http.server`; add `.html` when previewing.

## What comes from where

| Shown on the site | Source |
|---|---|
| Walkthrough decisions | `forge_vigil.policy.decide()` and the shipped fixtures and cases, at build time |
| Sample dashboard | `website/sample_dashboard.py` output, committed as `website/demo-dashboard.html`; the test rebuilds it and compares, so drift fails loudly |
| Test and deliberate-defect counts | `tools/handshake.py` counts and `tools/mutation_check.MUTANTS`, at build time |
| Version, commit and policy version (footer) | `forge_vigil.versions` and git, at build time |
| Measured results, limits, timeline, wording | `website/content.py`, transcribed from README and HANDOFF.md with checkpoint and version |
| Layout and copy | `website/build.py`; styles and the walkthrough script in `website/static/` |

## Accuracy rules

- Walkthrough outcomes are computed, never typed.
- Every measured result names its checkpoint and version. Add new measurements; never change an old
  one. Report misses next to successes.
- Keep the caveats: all evaluation cases are fictional and share an author with the policy. Make no
  claims about malware protection, field accuracy or hosting until ForgeVigil's records establish them.
- `tests/test_site.py` enforces the gap callout, the caveats, the CSP and safe output handling.

## Security headers

`static/_headers` sets a strict Content-Security-Policy (`default-src 'none'`, same-origin scripts,
styles, fonts and images only, no framing), HSTS and related headers. Pages contain no inline
scripts, styles or event handlers. CSS and JS are fingerprinted by content hash and cached long-term.
Fonts are IBM Plex (SIL Open Font License, `static/fonts/OFL.txt`), self-hosted.

## Releasing on Cloudflare Pages (forgevigil.com)

The site is released from a dedicated `website` branch, so nothing reaches forgevigil.com until
the operator moves that branch to a qualified commit. Merging to `main` alone deploys nothing.

**Build command** (identical in `.github/workflows/website.yml`, checked by `tests/test_site.py`):

```
python3 -B -m unittest tests.test_site && python3 -B website/build.py --release
```

The site tests run first. `--release` then refuses to build unless the git commit is known, the
tree has no uncommitted changes, and the commit equals Cloudflare's `CF_PAGES_COMMIT_SHA`, so every
published page names the exact commit it came from. The full qualification gate (Linux and Windows,
Python 3.11 and 3.13, including these tests) runs in `.github/workflows/qual.yml` before a commit is
promoted.

### One-time setup

1. Cloudflare dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git** →
   the ForgeVigil repository.
2. Build settings:

   | Setting | Value |
   |---|---|
   | Production branch | `website` |
   | Framework preset | None |
   | Build command | the command above |
   | Build output directory | `website/dist` |
   | Environment variable | `PYTHON_VERSION` = `3.13` |

3. **Settings → Builds → Branch control:** production branch `website`; preview deployments
   **None**, so feature branches never publish. Optionally set **Build watch paths** to
   `website/*`, `forge_vigil/*`, `tests/*`, `tools/*`.
4. Create the branch from a qualified `main` commit and let Pages build it:

   ```bash
   git push origin <qualified-main-sha>:refs/heads/website
   ```

   Check the `*.pages.dev` URL, then **Custom domains** → add `forgevigil.com` and
   `www.forgevigil.com`; redirect `www` to the apex with a Redirect Rule (301,
   `concat("https://forgevigil.com", http.request.uri.path)`).
5. Zone settings: SSL/TLS **Full (strict)**, **Always Use HTTPS**, minimum TLS 1.2, DNSSEC on.
   Leave **Web Analytics** and **Rocket Loader** off; they inject scripts the CSP blocks and the
   privacy page says the site doesn't use.
6. If the domain sends no email, publish `TXT @ "v=spf1 -all"` and `TXT _dmarc "v=DMARC1; p=reject;"`
   so nobody can spoof `@forgevigil.com`.

### Each release

1. Merge to `main`; wait for `offline-qualification` (Linux and Windows) and `website-build` to pass.
2. Fast-forward the release branch: `git push origin <that-main-sha>:refs/heads/website`.
3. Verify:

   ```bash
   curl -sI https://forgevigil.com | grep -iE 'content-security-policy|strict-transport'
   curl -s https://forgevigil.com/.well-known/security.txt
   ```

   The footer of every page shows the commit; it must match the promoted SHA.

The Pages build imports ForgeVigil's code and the test modules (to count them) and runs the site
tests. It runs no server, model or provider call.
